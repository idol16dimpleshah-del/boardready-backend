## What was found and fixed

**Readiness Core orbit-ring artifact.** The tilted ring meant to orbit the Readiness sphere was rendering as a broken, flattened "whisker" poking out from behind the sphere instead of a clean ellipse around it, in both themes. Root cause: `.core-orbit` and `.core-sphere` are sibling elements under `.core-wrap`, composited in plain DOM paint order — CSS 3D transforms only depth-sort *between* elements when a shared ancestor declares `transform-style: preserve-3d`, which `.core-wrap` never did, so the ring's `rotateX(64deg)` tilt was silently flattened to 2D and the opaque sphere simply painted over it wherever the two overlapped. Fixed by tightening the ring's footprint (`inset:0` → `inset:7%`, matching it to the sphere it circles) and removing the spin animation that was making the flattening artifact move and flicker (`animation: coreSpin …` and the now-unused `@keyframes coreSpin` block deleted entirely; the ring keeps its static tilt). The actual Readiness-percentage encoding (`setCore()`'s `--pctn` CSS variable and the SVG `stroke-dasharray` progress ring) was read and deliberately left untouched — this was a pure rendering-artifact fix, not a scoring or data change. Confirmed by screenshot in both themes: a clean sphere with no stray ring fragment.

**Card-language inconsistency.** The `.weakspot-hero` card ("Here's what to conquer next") used a different visual idiom — full translucent border, diagonal two-color gradient fill — from every other highlighted card on the page (`.mission-card`'s single left-accent stripe over a flat tint). Unified it onto the same idiom (`border-left:3px solid var(--violet)` over a flat `color-mix` tint), while deliberately keeping violet instead of switching to `.mission-card`'s amber — a genuinely different card gets a genuinely different accent color, but now expressed through the one card idiom the page actually uses everywhere else, not two.

**Primary-action inflation on the Results screen.** Three buttons — "Improve My Score", "Train this topic", "Retake this set" — all rendered as identical vivid-gradient primary buttons on the same screen, so nothing told a student which action was actually the recommended next step. "Train this topic" and "Retake this set" are now ghost-styled (`.p-btn-ghost`: tinted glass background, subtle border, no gradient), leaving "Improve My Score →" as the Results screen's one visually primary call to action. Confirmed by screenshot in both themes: the two secondary actions read as clearly secondary next to the one gradient CTA.

**List-row idiom inconsistency.** Three different row-list patterns — `.improvement-row` and `.mistake-list .mrow` (a thin top border between plain rows) and `.explain-item` (the same thin-border pattern) — didn't match the tinted, rounded, gap-separated row style already used elsewhere on the same pages (`.chapter-row`, `.ic-sub-row`). All three were converted to the same tinted-rounded-row treatment (`background: color-mix(in srgb, var(--ink) 3%, transparent)`, `border-radius`, `margin-bottom` between rows, no border-top), so a student scanning "where marks were lost" or the full answer review sees one consistent row language instead of three.

**Missing hover states.** Filter chips (`.p-chip`), tab buttons (`.tabrow button`), and topic-picker cards (`.pick-card`) had no visual response to a mouse hovering an inactive/unselected one — on a page with a real hover-capable pointer, that reads as unresponsive rather than intentional. Added a consistent, restrained hover treatment (`border-color` shift toward violet, small `translateY(-1px)` lift, matching the existing `.opt` and `.pick-card.sel` hover language already used for selectable options elsewhere) on all three, transition-backed so it's a smooth motion rather than a snap. Confirmed by screenshot: chip, MCQ option, and Next-button hover states all visibly react without disturbing layout.

**Toast snap instead of fade.** The confirmation toast (e.g. "Unlocked") appeared and disappeared via the `hidden` attribute — an instant cut, no transition, and (because `hidden` elements are fully removed from the accessibility tree) nothing for a screen reader to catch even with `aria-live` on it. Switched to a class-based show/hide (`el.classList.add/remove('show')`) driven by an `opacity`/`transform` CSS transition, and added `aria-live="polite"` now that the element stays in the DOM (off-screen/invisible via opacity, not `hidden`) so assistive tech can actually announce it. Re-verified against Phase 6's keyboard/axe scripts below to confirm this didn't reintroduce any accessibility regression.

**Typography-hierarchy inversion.** `.readiness-copy h3` ("Take a test to get your first Readiness Score") rendered at 15px — smaller than `.mission-card h3` at 18px, even though the Readiness card is the dashboard's top, most prominent card. Raised to 18px to match. `.dash-greet h2` ("Hi, ⟨name⟩") was slightly reduced (22px → 20px) so the greeting no longer visually outweighs the Readiness headline directly beneath it. `.core-caption` (the small copy under the Readiness sphere) dropped its italic styling and grew slightly (11px → 12.5px) for consistency with the rest of the card's body text, which is never italicized elsewhere.

**Login panel vertical centering.** `.login-panel` used `align-items: flex-start`, top-aligning the hero copy and the login card even when the viewport was taller than their combined content — leaving conspicuous dead space at the bottom on common desktop heights. Changed to `align-items: center` (desktop only; the existing sub-760px mobile override, which already centers the stacked layout for a different reason, is untouched). Confirmed by screenshot: both light and dark login screens now sit centered rather than pinned to the top.

## What was deliberately left alone

The exam timer's non-live-region behavior, the partial (not fully 24px) touch-target sizing on the question-navigator dots, and the mobile breakpoint layout choices from Phase 7 were all reviewed during the audit and confirmed as intentional prior decisions, not overlooked polish — they were left exactly as Phases 6 and 7 set them.
